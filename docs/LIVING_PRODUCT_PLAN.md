# Living product implementation

Approved scope: one local product model for people and coding agents, independent
of the optional Obsidian export. Existing evidence gates and the compact context
compiler remain authoritative.

## Delivery stages

- [x] Typed product/capability/service/contract/resource/flow catalog with source
  anchors, multiple dependencies per pair, intent versus observation, history,
  optimistic concurrency, environment and recorded deployment context.
- [x] SQLite-backed documentation with stable section identifiers, separate
  curated and generated text, source-specific freshness and review state.
- [x] Product, Repositories, Flows, Changes and Knowledge navigation; accessible
  editing, source drill-down, filters and a shared task-bundle workflow.
- [x] Bounded task bundles and conservative cross-repository diff impact with
  citations, explicit possible impacts and knowledge gaps.
- [x] Consolidated episode completion and lesson review, duplicate/conflict
  handling, expiration and separate verification/merge/acceptance signals.
- [ ] Hermetic end-to-end tests, independent review, UI verification, installation,
  representative real flow, capture evaluation and honest regression evidence.
- [ ] Publish main to origin and mirror; restore the company GitHub identity.

## Acceptance rules

Generated prose is never evidence. Declared product intent is never displayed as
observed runtime behavior. A hostname match only proposes a dependency. A task
bundle states its source view and gaps, stays within its budget, and does not
change the existing stable injection prefix. Existing data and optional vault
exports are preserved. Failed model runs remain in benchmark denominators.
