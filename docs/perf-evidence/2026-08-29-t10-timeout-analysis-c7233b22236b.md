## Question

Did the t10 brain arm time out because injected context distracted the agent, or
because the task/model run was intrinsically difficult?

## Preserved observations

| Arm | Result | Wall | Agent output | Validation |
| --- | --- | ---: | ---: | --- |
| brain | timeout | 1,800,299 ms | stdout 0 B; stderr 0 B | not run |
| off | pass | 1,037,582 ms | stdout 1,789 B; stderr 0 B | full suite + t10 acceptance passed |

The brain artifact files were created at `2026-08-29T05:16:26-0700`. They
remained empty when the harness killed the process group at the 1,800-second
deadline. The off arm began immediately afterward at
`2026-08-29T05:46:26-0700` and completed at `06:03:43-0700`.

The off arm made the intended change: after a transient failure it compared the
already-incremented attempt count using `>=`, moved exhausted work to the
terminal `Exhausted` state, and left the separate backoff bug untouched. That is
the family-D ground truth.

## Finding: null

The preserved data cannot distinguish injection distraction from ordinary
model/run variance. This is a **null diagnostic result**, not evidence for
either explanation.

The local launcher used Claude Code's text print mode. Claude Code emitted its
final summary only after the agent completed; because t10 was killed first,
both output files are empty. The evaluation runner also deletes the isolated
worktree and per-arm database when the matrix finishes, so there is no partial
diff, turn transcript, proxy request trace, or memory-use telemetry left to
inspect. Runtime alone is insufficient: the off arm itself needed 17.3 minutes,
and one seed cannot separate a treatment effect from sampling variance.

## Instrumentation consequence

Subsequent wrappers must use incremental `stream-json` output and retain safe
per-turn diagnostics. A timed-out run should preserve at least:

- the last completed model/tool event and timestamp;
- a redacted request count plus input/cache-read/cache-write/output tokens;
- the partial Git diff (with the synthetic-fixture-only rule enforced); and
- the byte digest and byte length of every injected context block.

Seeds 2-3 are therefore the next evidence for the t10 outcome. Until those
replicate, round 1's t10 result remains a timeout loss with unknown mechanism.
