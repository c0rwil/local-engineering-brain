Ordinary phone-task status polls should return status, terminal, step_count, result and error without the steps payload. Add include_steps to opt into history and since_step to request strictly newer step numbers; a non-null cursor implies inclusion even when include_steps is false, while step_count remains the total. Default polling must not load all step payloads from Redis.

The false-value rule applies only to include_steps: boolean false or a trimmed, case-insensitive string false disables that flag; boolean true or string true opts into history. Parse since_step separately. An absent or null cursor means no cursor. For every other cursor value, preserve Python int conversion behavior: false converts to 0, true to 1, finite numeric fractions truncate toward zero, and integer strings (including surrounding whitespace and a sign) are accepted. Negative converted cursors are allowed. Text such as "false" or "1.8", empty strings, arrays and objects cannot be converted and must return JSON-RPC invalid-params (-32602), without loading history. In particular, since_step=false requests all steps above 0; it does not disable history.

Preserve contract v1 and the device wire contract semantically: every existing fixture key, scalar type and value, and array order/length must remain intact. Additive optional object fields, including step_count on legacy status examples, and JSON whitespace or object-key ordering changes are allowed. A new v2 fixture directory is optional. Keep full step wire fields and update consumers that actually need step content to request it explicitly. Add focused regression coverage.
