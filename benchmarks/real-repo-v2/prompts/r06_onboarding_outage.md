A backend outage or hung users/me request can break every gated page. Make onboarding checks fail closed within five seconds, preserve safe invite and CLI return paths, and keep the welcome page usable without redirect loops. Completed users should still reach their intended safe destination. Malformed JSON, failed and unreachable backend responses must not admit a user to gated pages. Add regression coverage.

The five-second limit covers the complete backend operation, including waiting for response headers and consuming/parsing the response body. A stalled body must also settle safely within that total deadline. Header/request timeouts may report either 503 or 504; interrupted body failures may report 502, 503, or 504. Preserve the existing failure-result shape, ordinary HTTP error statuses, 503 for an unreachable backend, and 502 for malformed JSON. Any implementation meeting these observable behaviors is acceptable; no particular cancellation mechanism is required.

Preserve the repository's existing return-path policy: require a path beginning with `/` that remains on the same origin after URL parsing, and keep its normalized path, query and fragment. Reject external or protocol-relative destinations, including those exposed by control-character normalization; reject a `/welcome` pathname to avoid self-bounces. Also preserve the existing invalid-route rule that rejects a pathname containing `://`, such as `/https://example.com/path`. That last case is a local invalid route, not an off-site URL. For a rejected destination, the gate falls back to `/welcome` without a next parameter, and a completed user leaving welcome falls back to `/me`.
